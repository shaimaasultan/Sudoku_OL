How the tensor method works

  1. The cube is one tensor. A point (row, column, number) is true while that number can still go in that cell. The same tensor is kept in four views, and each view packs one line of the cube into a 32-bit word: a cell's numbers (the pillar), a number's columns in a row, its rows in a column, and its places in a box. Removing a point changes all four views at once.
  2. Lines with one point. Every rule of Sudoku says "exactly one point on each line". A line with no point is a dead end; a line with one point places it. On pillars this is a naked single; on the other three views it is a hidden single — one pass over the tensor finds both.
  3. Layers in four directions. A layer is a slice of the cube with its list of options. A number layer (horizontal slice) lists every way to place that number once in each row, column and box — the templates of the lean method. A row, column or box layer (vertical slices and prisms) lists every way to give its open cells different numbers. The default setting uses the box prism as the vertical layer: a whole box (3×3 cells on 9×9) standing through all the number slices, instead of a slice one cell thick — in the cube it is drawn as a shaded prism.
  4. Thinnest first, in any direction. For each layer a size bound is worked out from the tensor (the product of the open points along its lines). The start builds the top 1–9 thinnest layers; when nothing changes, one more is built, the thinnest in any allowed direction. A layer with more options than the cap is left unbuilt, and tried again only when its bound has shrunk about 8 times.
  5. Cut and AND / OR. An option that uses a removed point is cut. A point used by no option is removed from the tensor (OR); a point used by every option is placed (AND). The same rule works for all four directions.
  6. Guess last, on the smallest choice. When nothing more can be done, guess on the built layer with the fewest options or on the tensor line with the fewest points, whichever is smaller; go back if it leads to a dead end.

Dancing Layers

  1. Exact cover with whole templates. For the thinnest numbers (the Start menu) whose layer fits the cap, every template is one row: it covers its N cells and the column "number d". Every other number keeps ordinary rows: one per possible cell, covering that cell and "d in its row / column / box". A solution is a set of rows that covers every column exactly once.
  2. Toggle, don't rebuild. Choosing a row unlinks every row that clashes with it — all templates and candidates through its cells; going back links them again (Knuth's dancing links). No list is ever cut, copied or built again during the search.
  3. Choose the smallest column. Every step works on the column with the fewest live rows: a cell, a whole number layer (choose one of its templates), or a number in a row, column or box. A column with one row is a forced move; with none, a dead end.
  4. With Start = no layer, it is plain Dancing Links on the candidates the givens leave open — the race lists it separately, so the effect of the templates can be seen.

The shared-patterns version

  1. One build for several numbers. A number layer's template is a pattern — one cell per row, column and box — and the pattern does not depend on the number. So the thinnest numbers (the Start menu: top 2, 3, …) are built in one walk over the patterns. Each pattern is kept once, with a number mask: the numbers every one of its cells still allows. A branch of the walk stops as soon as the mask is empty.
  2. No re-cutting. Each point keeps a support count — how many live patterns use it for its number — and each number keeps how many patterns are still live for it. When a point is removed, only the patterns through that cell are touched: they lose that number's bit and their cells' counts go down. Support 0 removes a point (OR); support equal to the number's live count places it (AND); a number with no live pattern is a dead end. The big list is never scanned again.
  3. Undo instead of copy. Every bit cleared is written to a trail; after a failed guess the trail is played back, so the list is shared by all guesses and never copied.
  4. When nothing more follows, one more number is added to the shared set (a new walk), as the lean method adds a layer. A walk longer than the cap is dropped and tried again only when the numbers have shrunk about 8 times.

The matrix (matmul) version

  1. The tensor is one flat 0/1 vector x of all N·N·N points. A is the fixed matrix of the 4·N² lines of the cube; the line sums s = A·x give the dead ends (0) and the singles (1) in one product.
  2. Every row, column and box layer is built in full at the start (all its options; a layer over 300,000 options waits until it shrinks). Only the top 2 or 3 thinnest number layers are built, and no more later.
  3. All the layers of one direction are stacked into one option × point matrix M. One pass is two products: alive = (M·(1−x) = 0) cuts every option that uses a removed point, and count = aliveᵀ·M counts how many live options use each point. Count 0 removes the point (OR); count equal to its layer's live options places it (AND).
  4. Guess last on the smallest choice, as above; a guess on a layer just switches off the other rows of that layer in alive.

Row, column and box layers with AND / OR find every naked and hidden set in a unit (pairs, triples, …); number layers find the fish patterns (X-Wing, Swordfish, …). Using both directions sees both kinds of reason. Nothing here uses the language or move words; only small counters (layers built, guesses) are kept for the table.
